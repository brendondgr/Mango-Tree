# Global Skill

This skill applies to every query and every agent working in this repository.

## Step-and-commit workflow

When implementing a plan or executing repository changes:

1. Complete one plan step or one logical unit of work.
2. Validate that step (tests, build, lint, or other acceptance check defined by the plan).
3. If validation passes and there are file changes, create a git commit before starting the next step.
4. If validation fails, fix the issue and re-validate. Do not commit broken work.
5. If a step produces no file changes, skip the commit and proceed.

One validated step equals one commit. Do not batch multiple validated steps into a single commit unless the user explicitly asks.

## Commit messages

Write concise commit messages that describe what changed and why. Focus on the repository change, not the agent session.

**Never include AI or tool attribution**, including:

- `Co-authored-by` lines naming an AI, Cursor, Copilot, Claude, GPT, or similar
- Phrases like "Generated by", "AI-assisted", "written by the assistant"
- Sign-offs referencing the model or agent

**Good:**

```
fix(chat): stop typing indicator after stream ends

Clear the indicator when the final chunk arrives so it does not linger.
```

**Bad:**

```
fix(chat): stop typing indicator after stream ends

Generated by Claude. Co-authored-by: Cursor <noreply@cursor.com>
```

## Git safety

Follow the repository git safety protocol:

- Run `git status`, `git diff`, and `git log` before committing.
- Never update git config.
- Never skip hooks (`--no-verify`, `--no-gpg-sign`, etc.).
- Never run destructive git commands unless the user explicitly requests them.
- Do not commit secrets (`.env`, credentials, keys).
- Do not amend unless the user requests it or a hook auto-modified files after a successful commit you created.

On Windows PowerShell, pass multi-line commit messages with a here-string:

```powershell
git commit -m @"
fix(chat): stop typing indicator after stream ends

Clear the indicator when the final chunk arrives.
"@
```

## Scope

- **Applies during**: plan execution, multi-step implementation, refactors, feature work, bug fixes with repository edits.
- **Does not override**: read-only questions, reviews with no changes, or explicit user instruction to defer commits.

When the user says not to commit yet, wait until they ask or until the next validated step after they lift that restriction.
